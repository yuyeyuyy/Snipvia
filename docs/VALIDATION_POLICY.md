# 验收与打包结果复用

同一份代码已经验收通过，就复用记录，不因提交、推送、重新打包或上传失败重新运行整套功能验收。

## 按变化选择检查

| 变化 | 需要执行 | 可以复用 |
| --- | --- | --- |
| 只改文档或版本号 | 文档差异检查；新版本构建和产物检查 | 已通过的功能单测与 Electron 验收 |
| 功能代码、依赖、IPC 或测试变化 | 对应单测、类型检查与受影响 Electron 流程；无法确定影响范围时再扩大 | 输入未变的其他功能验收 |
| 只改打包工具 | 工具自身检查；新构建与产物验证 | 业务功能验收 |
| 已冻结安装包再次上传 | 版本、大小、SHA-256 与远端结果核对 | 该哈希对应的签名、公证与完整性结果 |

失败、跳过、未运行不能记为通过。Windows 真机、真实模型、权限与混合 DPI 未验证时保持“待验证”，不能从 macOS 结果推断。

## 一次构建供两个平台使用

`pnpm release:prepare` 检查输入与 `out/` 内容哈希；macOS 使用：

```sh
node scripts/macos-release/release.cjs --execute
pnpm dist:windows
```

两个入口自动调用同一个准备工具。macOS 另检查 Swift 源码、编译脚本、Xcode/Swift 版本和三份 Helper 二进制。匹配时复用构建，缺文件、哈希变化、工具链变化、记录损坏或上次失败时重新构建。每次安装包仍使用独立新目录。

本地凭据位于 `.dev-runtime/release-build/{desktop,native}.json`，只含哈希、时间和 Node 版本，不包含环境变量值、API Key 或钥匙串内容。桌面输入包含源码、测试、根配置、脚本、素材、声明和已安装依赖锁记录；输出包含 `out/` 全部普通文件与权限。会影响构建的 Vite 环境变量也进入哈希。文档变更不触发重建。

这些记录是同一台受信开发机的增量构建凭据，并非跨机器供应链证明。手工更改 `node_modules/` 后，删除对应本地构建记录并重新安装锁定依赖；切勿人工填写 `passed`。构建期间不要并发改动源码或运行另一份构建。

## 新产物只验一次

新 macOS 包仍须通过 Developer ID、时间戳、Hardened Runtime、最小 Entitlements、Apple Accepted、Staple、Gatekeeper 和容器内应用检查。新 Windows 包仍检查 PE、版本、图标、安装权限、ASAR、NSIS 解包与哈希。不同容器内提取的 APP 需要各自验证，不能只凭文件名跳过。

同一原始 APP 的校验结果在本轮报告内直接复用，不再为了生成报告重复执行。每个架构完成后立即保存 `verification-arm64.json` / `verification-x64.json` 检查点，记录实际验收结果和冻结产物 SHA-256，后续失败可保留复用依据。冻结后仅核对哈希即可复用此次签名、公证结果；任何字节改变都使旧结果失效。
