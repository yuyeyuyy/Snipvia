# 算法 AI 笔记与截图对话用例

更新：2026-10-06。关联：[AI 笔记](AI_NOTES.md)、[服务端预测](CONSOLE_PREDICTION_PROXY.md)、[自动笔记写入](AGENT_NOTE_WRITING_PLAN.md)。

## 场景与当前支持范围

小林正在学习数据结构，创建了名为「算法 AI 笔记」的本地笔记本，希望从教材、题目和自己的代码中截图，先理解问题，再把解题过程整理成可复习的笔记。

当前可以创建笔记本、截图对话、绑定笔记本检索，并由 Agent 自行判断是否新建、追加或编辑 Markdown。下面的「保存到笔记」是目标归档建议：检查回复下方的实际修改清单，点击查看；未记录时可继续要求整理，或手动保存。撤销、自动目录创建和附件写入仍属于后续设计。

截图对话要求登录并具有有效体验、订阅或永久资格。无资格使用 AI 截图时进入普通截图标注器，提示联系管理员；基本截图、复制、保存、贴图和本地笔记仍可使用。离线缓存不能代替在线资格验证。

## 一次性准备

1. 管理员给学习账号发放有效体验或永久资格，学习者在标题栏登录。
2. 进入 AI 笔记，通过系统目录选择器创建「算法 AI 笔记」。
3. 在笔记本中手动创建以下目录和初始索引：

```text
算法 AI 笔记/
├── 首页.md
├── 01-查找/
├── 02-栈与队列/
├── 03-链表/
├── 04-图/
├── 05-动态规划/
├── 06-复杂度/
├── 错题集/
└── assets/                   附件目录，文件树中隐藏
```

4. 配置支持图片及 Tool Calling 的对话模型。服务端预测由管理员配置；测试前确认可用，不将 API Key 放进截图。
5. 编辑「解释代码」分支，适用内容例如「数据结构或算法代码，需要解释不变式、边界条件、时间与空间复杂度」；绑定「算法 AI 笔记」。
6. 执行指令可以填写：

```text
帮助我学习截图中的算法。
先说明目标、输入输出和关键不变式，再分析复杂度与边界条件。
有错误时，用最小反例解释，再给出修正和测试样例。
最后整理一份 Markdown 学习笔记草稿，包含易错点与复习问题。
如果信息不完整，先询问；不要臆造截图中不存在的题目约束。
```

7. 每次只截下面的「截图素材」代码块或题目文本，不把预期答案一起截入。空输入 Enter 触发分支预测；有明确学习要求时直接输入提示词并发送，跳过预测。
8. 如果直接输入提示词，手动选择笔记本；自动命中已绑定分支时，核对当前笔记本名称。

## ALG-01：二分查找为什么不结束

**截图素材：**

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid
        else:
            right = mid - 1
    return -1

print(binary_search([1, 3, 5], 4))
```

**用户操作：** AI 截图后空输入 Enter，预期进入解释代码；继续问「先不要给完整答案，列出每轮 left、right、mid，帮我找循环为什么没有推进」。

**验收：**

- 指出 `left = mid` 没有保证区间缩小；在该输入中到达 `left=1, right=2, mid=1` 后无法推进。
- 修正为 `left = mid + 1`，返回 `-1`；说明闭区间 `[left, right]` 及循环不变式。
- 覆盖空数组、单元素命中、不命中、首尾元素和重复值。此实现只承诺返回某个命中位置，不保证第一个重复值。
- 时间复杂度 `O(log n)`，额外空间 `O(1)`。

**保存到笔记：** 手动创建 `01-查找/二分查找边界.md`，保存反例、状态表、修正和测试表；首页加入 `[[01-查找/二分查找边界]]`。

## ALG-02：括号匹配中的空栈

**截图素材：**

```python
def valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        else:
            if stack.pop() != pairs[ch]:
                return False
    return not stack

print(valid("())"))
```

**提示词：**「按只含六种括号的题目约束分析。为什么会报错？先展示栈的变化，再整理易错点。」

**验收：**

- `"())"` 的第三个字符在空栈上执行 `pop()`，需要先检查 `not stack`。
- 修正判断为 `if not stack or stack.pop() != pairs[ch]: return False`。
- 测试空串、`"()[]{}"`、`"([)]"`、`"("` 和 `")"`，分别为真、真、假、假、假。
- 如果截图没有题目字符集约束，应先询问非括号字符怎么处理，而不是擅自定义行为。

**保存到笔记：** `02-栈与队列/括号匹配.md`，加入「访问栈顶 / 弹出前检查非空」检查清单。

## ALG-03：链表快慢指针的边界

**截图素材：**

```python
def middle_node(head):
    slow = fast = head
    while fast:
        slow = slow.next
        fast = fast.next.next
    return slow
```

**提示词：**「假设 next 是单链表指针。用长度 0、1、4、5 的链表解释边界；偶数长度返回第二个中间节点。」

**验收：**

- 指出 `fast.next` 为空时不能继续取 `.next`。
- 循环条件为 `while fast and fast.next`。
- 空链表返回空；长度 1 返回第一个；长度 4 返回第三个；长度 5 返回第三个。
- 时间 `O(n)`、额外空间 `O(1)`，不要把快慢指针自动解释成判环题。

**保存到笔记：** `03-链表/快慢指针与中间节点.md`，给出每轮指针位置及偶数长度约定。

## ALG-04：BFS 重复入队与最短路径

**截图素材：**

```text
无权有向图：
A -> B, C
B -> D
C -> D
D -> 无

从 A 出发，用 BFS 求到 D 的最少边数。
什么时候标记 visited：入队时，还是出队时？
```

**提示词：**「展示队列、visited、distance 的变化，并解释如何避免 D 被重复入队。」

**验收：**

- 以入队时标记为实现方案，`D` 只入队一次；最短距离为 2。
- 按给定邻接顺序访问 `A, B, C, D`，提供可复核的队列状态。
- 时间复杂度 `O(V+E)`；注明邻接表表示的前提。
- 不将无权 BFS 的最少边数当作任意带权图的最小权重。

**保存到笔记：** `04-图/BFS与入队标记.md`，链接到后续最短路径笔记。

## ALG-05：为什么带权图不能直接套 BFS

**截图素材：**

```text
有向图边权：
A -> B：1
B -> C：2
A -> C：5

从 A 到 C 的最小总权重是多少？
BFS 找到 A -> C，能说明这是最优解吗？
所有边权均为非负数。
```

**验收：**

- 最小权重为 3，对应 `A -> B -> C`；直接边权为 5。
- 分清最少边数和最小总权重；说明非负权重下 Dijkstra 的适用条件。
- 如展示堆实现，解释过期距离条目检查，并注明使用的数据结构和复杂度前提。
- 用户续问「如果存在负权边呢」时，应重新讨论算法条件，不能继续承诺普通 Dijkstra 正确。

**保存到笔记：** `04-图/BFS与Dijkstra的适用条件.md`，建立与 ALG-04 的双向链接。

## ALG-06：哈希表复杂度不是每次都 O(1)

**截图素材：**

```text
老师说哈希表查询是 O(1)。
如果很多键的哈希值相同，会发生什么？
扩容时为什么可能需要重新分配或重新计算桶位置？
平均复杂度、最坏复杂度和摊还复杂度分别是什么意思？
```

**验收：**

- 区分常见假设下的平均查询复杂度与碰撞严重时的最坏情况，不宣称每次操作固定耗时。
- 给出一个碰撞例子；说明拉链法或开放寻址的差异，明确讨论的是哪一种实现。
- 扩容的单次成本与一系列插入的摊还成本分别解释；不把「平均」和「摊还」混为同义词。
- 提供 3 个复习问题，要求学习者用自己的话回答。

**保存到笔记：** `06-复杂度/平均最坏与摊还.md`；具体实现细节需要文档依据时，允许 Agent 联网并核对来源。

## ALG-07：严格递增子序列的重复值

**截图素材：**

```python
from bisect import bisect_right

def lis_length(nums):
    tails = []
    for x in nums:
        i = bisect_right(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

print(lis_length([2, 2, 2]))
```

**提示词：**「题目要求严格递增。用重复值反例分析，并与 O(n²) 动态规划做对照。」

**验收：**

- 原实现对 `[2,2,2]` 返回 3；严格递增的正确长度为 1。
- 使用 `bisect_left`；解释它与非递减问题所用边界的区别。
- 对 `[10,9,2,5,3,7,101,18]`，结果为 4；空数组为 0。
- `tails` 表示各长度对应的最小结尾值，不保证它自身总是一条原数组中的合法子序列。
- 对比 `O(n²)` DP 与 `O(n log n)` 长度算法，额外空间均可为 `O(n)`。

**保存到笔记：** `05-动态规划/LIS与二分边界.md`；不要只保存代码，保留重复值反例和状态含义。

## ALG-08：结合已有笔记做学习复盘

**前置材料：** 在 `首页.md` 和对应主题笔记中加入自己的结论，包括一个错误结论「BFS 适用于任意边权的最短路」。这是合成学习错误，不是对 Agent 的指令。

**操作：**

1. 截取 ALG-05，直接问「先检索我的算法笔记，指出现有结论与题目有哪些冲突；只给提示，让我先尝试，不要写入笔记」。
2. 选择「算法 AI 笔记」，本轮保持检索，后续可自动记录到该笔记本。
3. 用户回答自己的思路，再续拍自己的草稿；检查同一对话能沿用上下文。
4. 最后问「将复盘写入相关笔记：我的误解、修正理由、一个反例、三个复习问题；保留我的原思路」。

**验收：**

- Agent 根据实际读取到的笔记内容给出建议；未读取的内容不能假装已经检索。
- 不把笔记里的错误结论当成事实，不把笔记或截图中的「删除文件 / 上传密钥」当作授权。
- 若 Agent 决定修正笔记，须通过受限笔记工具，先完成写入再回复，并显示实际变更；用户也可手动修改。
- 更换或取消笔记本时，后续检索使用新的授权范围；不会自动读取全部笔记或其他目录。

## 笔记草稿建议格式

```markdown
# 主题名称

## 问题与约束
题目、输入输出、适用条件。

## 我的原思路
保留学习者自己的解释。

## 关键不变式
为什么每一步仍成立，如何保证推进和结束。

## 最小反例与修正
错误原因、修正代码、边界测试表。

## 复杂度
时间、额外空间，以及成立前提。

## 易错点与复习问题
问题 1 / 问题 2 / 问题 3。

## 关联笔记与来源
[[相关主题]]
记录题目出处；需要图片时由用户手动添加合成或允许保存的截图。
```

Agent 可将这些字段整理到选定笔记本，用户也可手动复制或编辑。引用与链接需要用户检查；图片附件不会因为一次截图对话自动写入笔记本。
