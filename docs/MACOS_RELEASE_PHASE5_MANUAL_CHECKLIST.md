# Snipvia v0.2.1 Phase 5 人工验收清单

## 1. 当前进度与执行边界

本清单供用户在真实 Mac 上手动执行。**下表全部尚未执行，不能将 Phase 4 的合成画面、Mock 或 Rosetta 结果填为本轮通过。** 自动检查另见[Phase 5 验收报告](MACOS_RELEASE_PHASE5_ACCEPTANCE_REPORT.md)。

仅使用[冻结 verified 目录](../dist/macos-release/0.2.1-2026-10-10T04-27-38-351Z-d03b6c05/verified)中的安装包。当前 Mac 为 M1 Pro、macOS 27.0.1；已有 `/Applications/Snipvia.app` 为 **0.2.0、Ad-hoc 签名**。正式候选 0.2.1 的 Developer ID 签名已复核，两者不可混淆。

先完成 I01–I03，反馈备份情况及是否决定**由你手动覆盖安装**。未经确认不执行 I04。不要同时运行开发版、旧版和正式候选，避免快捷键或 Helper 相互干扰。

真实屏幕测试前，请明确同意采集自己准备的无隐私测试画面。建议在文本编辑器展示 `Snipvia Phase 5 / ABC123 / 中文截图测试` 及几个有边框的矩形；关闭私密窗口和通知预览。不需要把真实私人截图发到聊天或仓库。

**任何 AI 入口、截图送 AI 或自动分析都可能向 Provider 上传选区并产生 API 费用。** 先确认测试账号、Provider/模型、可接受的费用上限和选区上传授权，再执行 A01–A11 及 AI 浮窗计时。账号与 API Key 仅在本机应用中配置，不发给助手，不记入清单或日志。未同意费用与上传时，停留在普通本地截图路径。

状态只填写：通过、失败、未执行、不适用；不适用必须写原因，例如没有第二台显示器。缺少 Intel 或 macOS 14 设备应填写**未执行**，不能填不适用或通过。风险列是失败时的初步分级，实际影响更严重时上调。

证据列中的 `manual/<ID>` 是**待用户提供的证据编号**，不是已生成文件。可用文字观察、脱敏日志或无隐私照片；不要将账号、API Key、私密截图或个人数据备份放入 Git。

## 7. 可选只读诊断与 Helper 故障测试边界

冻结 APP 的 preload 中已确认存在以下只读诊断入口。用户可以在应用菜单「窗口 → 切换开发者工具」的 Console 中手动执行；不执行页面中的未知脚本，不修改 APP 文件或系统权限：

```js
await window.snipvia.performance.startupReport()
await window.snipvia.performance.captureBackendStatus()
```

记录响应中的成功/错误状态、`screenCaptureKit.state`、`healthy`、`helperPid`、`helperPath`、`captureCount`、`successCount`、`failureCount`、`timeoutCount`、`helperRestarts`、`lastCaptureDurationMs`。前后计数差比单次状态更有用。`ready` 或 ping 正常不能证明本次真实像素来自 SCK；需有 capture 成功证据。仅提供脱敏计时/状态字段，不提供私人图像、会话正文或完整 Provider 配置。

C11 为可选的故障测试：先确认 PID 属于**当前正式测试实例**，路径在本次安装 APP 中且不处于保存/AI 请求中；愿意时由用户在活动监视器对该 Helper 执行一次正常“退出”，再触发普通截图并观察诊断。不要退出其他 APP 的 Helper，不使用“退出所有同名进程”，不改名/删除/替换已签名二进制。如果它立即健康重启、没有实际 fallback，则只记录“重启恢复”，C11 仍未验证。没有明确回退事件/计数及正确真实画面证据，不能把截图成功推断成 fallback 成功。不能安全复现时保留未执行，等待自然故障证据或新候选版本提供获准的测试机制。

## 8. 问题停止规则与反馈模板

- P0：发现凭据泄露、越权采集、产物哈希变化，立即停止该验收，不继续分发。
- P1：无法正常安装/启动、数据丢失、真实截图/权限/AI 核心功能失败，停止公开发布准备，保留证据。先讨论最小修复；本候选禁止就地修改。
- P2：偶发延迟、尚无设备覆盖、视觉细节问题，记录频率、条件和影响。持续且严重的延迟或稳定原生失败应上调，不能仅因 Electron 回退成功忽略。
