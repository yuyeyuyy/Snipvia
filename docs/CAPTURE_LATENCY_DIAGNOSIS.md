# 截图快捷键延迟排查（2026-10-10）

## 状态

**主要交互阻塞已修复，用户已通过真实快捷键测试确认「已经明显顺畅」。** 原生捕获的间歇超时仍可复现，底层根因尚未完全确认；不宣称所有捕获都能即时完成。

## 保留的修正

- `src/main/index.ts`：进入截图即开始计时；不在弹出本地选区前等待云端账号刷新；过期异步入口不能重新启动已取消的会话。
- `src/main/account/AccountService.ts`：增加同步的本地资格提示，仅用于选择截图模式。进入 AI 会话前仍执行服务端权限验证；没有绕过会员限制。
- `tests/unit/account.test.ts`、`tests/integration/capture-account-latency.spec.ts`：覆盖账号网络阻塞、资格撤销、取消后晚到的结果不能复活窗口。
- `tests/integration/screenshot-membership.spec.ts`：模拟授予资格后显式刷新客户端账号状态。
- `scripts/test-capture-normal-launch.mjs`：正常参数启动 Electron、临时资料目录、真实像素仅驻留内存，调用已注册的普通截图快捷键回调；检查后台启动、连续截图、取消和原生回退。没有物理按键注入，不保存截图，不调用 AI。

## 为什么之前的自动化可能偏快

Playwright Electron 启动器会添加后台节流及绘制相关 Chromium 开关；模拟截图也不经过 ScreenCaptureKit。原计时起点还在 AI 账号刷新之后，漏掉了云端等待。以上三个差异应分别考虑，不能以合成截图的耗时证明用户实际按键足够快。

## 已观察但未解决

- 常规路径运行原生 Helper 时，捕获请求可触发 500ms 超时，再回退 Electron；最近三个样本截图就绪为约 744 / 702 / 801ms。
- 真实开发应用曾出现 `showInactive()` 阻塞约 513ms；部分隔离测试没有此现象。因此窗口显示阻塞和原生捕获等待不可混为同一根因。
- 实验将 Helper 的阻塞 stdin 读取移到后台并运行主事件队列，临时路径出现约 197–227ms 无回退样本，但正式路径仍超时。二进制路径与启动上下文存在混杂，不能证明事件队列改动已经解决根因。该实验已撤回，原生源码与窗口预显示行为均恢复。
- 未收集到用户物理按键的完整分段样本。

## 下一步边界

优先用同一 Helper 路径、同一启动方式做对照，核实后台状态、系统回调和实际执行二进制；不要继续把不同路径的快速样本直接归因于源码修正。无需重做 UI 审查或全量测试。真实用户笔记窗口的自动读取曾被自动审批拒绝，不能以调试端口等方式绕过；应使用隔离窗口或由用户手动触发并只收集计时。


## 本轮交互修复与验收

- macOS 原生路径在画面尚未准备好时即呈现选区，并接受拖动。提前松手的选区与会话绑定，等画面解码后完成裁剪。
- 原生失败回退 Electron 时，只暂时隐藏覆盖层以避免截到自己的 UI，不重置当前选区；取消仍会结束会话并释放画面。
- AI 快捷键触发后并行进行资格预检，不阻塞本地选区。选区完成后先在内存中展示本地贴图与验证状态，不创建历史记录、不发起 AI 请求；校验通过后再升级为 AI 会话。
- 无会员的普通截图与编辑器保持原有行为，提示联系管理员；撤销资格仍阻止实际 AI 请求。
- 对话窗口在框选阶段提前创建与加载，等待现有窄 IPC 的 React 就绪通知。关闭时仍销毁窗口并释放 Agent 所有权；不改 ScreenCaptureKit Helper、AI 请求协议或截图数据格式。
- 贴图从本地图像升级为 AI 图像时不重新显示窗口或抢走对话框焦点；预加载对话的迟到状态不会覆盖新截图。
