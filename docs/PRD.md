# Snipvia 初期需求文档

版本：0.1 Draft · 日期：2026-09-16 · 状态：可用于拆分开发任务，待实机验证

## 2026-10-23 V2 Phase 1 产品决策

V2 以高性能截图、连续收集的未来演进、便捷编辑和快速输出为方向。本阶段只实现设置中心、旧 AI/笔记产品清理、独立截图模型与最小持久化、统一模式路由、旧记录只读兼容。快速截图复制并复用本地贴图，编辑截图复用原标注器；Collect 与外部目标只预留，未启用快捷键或收纳界面。

旧版数据和配置原位保留；Schedule 暂停主动提取、只读展示历史。截图不再创建 Conversation、不读取 API Key、不发起模型请求。更新渠道、主题、权限和应用身份保持。以下 2026-10-16 及更早描述属于 V1 历史产品，不能当作 V2 当前界面或承诺。实际变更和验证见 [V2 报告](v2/PHASE1_REFACTORING_REPORT.md)。

## 2026-10-16 产品决策

macOS / Windows 桌面核心完全免费、本地优先、无需登录或会员。用户配置大模型及 API Key；Phase 1 的预测直接使用用户视觉模型。Jev 图片模型为可选配置，由用户自备 Key、客户端直接调用。截图、编辑、对话、笔记、Agent 和系统/文件权限保留；服务端、管理后台与官网保存在私有工程。模型服务可能收费，本地优先不代表默认离线推理。以下早期规划中的未实现能力仍不是交付承诺。

## 1. 产品定位与目标

Snipvia 是一款截图驱动的桌面 AI 助手。用户通过快捷键框选内容，在截图附近开启一次独立 AI 对话，或选择“速记”，将截图中的安排整理成可确认的日程。

核心用户是频繁处理聊天、邮件、文档的职场人士。核心问题是将屏幕信息转交 AI 的操作繁琐，以及聊天中的安排容易遗漏。

核心路径：**框选 → 问一下 / 速记 → 获得答案 / 确认保存 → 回到工作。**

首版成功标准：两端都能稳定完成上述路径；日程日期与写入状态可信；使用过程无需复制图片、切换到独立 AI 网页。

## 2. 平台与产品边界

| 项目 | v0.1 决策 |
| --- | --- |
| macOS | 计划 macOS 14+，arm64 / x64 分别打包与验证 |
| Windows | Windows 11 x64；Windows ARM 和 Windows 10 暂不承诺 |
| 界面 | 简体中文优先，文案集中管理，为英文保留能力 |
| 截图入口 | 本应用全局快捷键、托盘/菜单栏入口；不是接管系统截图 |
| 日程 | 应用内保存与提醒；可导出 ICS 供用户手动导入 |
| AI | 支持图片输入的模型；内测由用户配置 API Key |
| 数据 | 本地保存；主动提问或速记时，将所选图片发送到配置的 AI 服务 |

截图快捷键候选为 macOS `Command+Shift+Space`、Windows `Ctrl+Shift+Space`；“续拍并继续对话”默认为 `CommandOrControl+Shift+Enter`。第二快捷键同样先进入区域框选，新截图接入最近会话的消息上下文并跳过自动意图分析。两个组合都允许实时录制修改，首次运行检测注册结果，冲突时保持旧设置并提示；输入法和常用软件冲突必须实测。

截图只支持单次框选一个显示器内的区域；副屏、不同缩放比例和负坐标必须支持。跨显示器连续框选推迟到后续版本。

## 3. 核心场景

### 3.1 截图问答

1. 用户触发快捷键，进入区域选择。
2. 拖动框选，松开后在选区邻近显示浮窗。
3. 浮窗固定显示裁剪图与胶囊操作区；用户可直接开始对话，也可按 `Control+C` 将图片复制到系统剪贴板并关闭浮窗。
4. 输入问题后开始流式回答；后续问题沿用同一截图与对话。
5. 用户可以停止回答、复制文本、拖动浮窗、固定浮窗或关闭。

普通截图快捷键默认新建会话；历史页可重新打开旧会话。只有用户明确按下“续拍并继续对话”快捷键时，才会用新截图替换该会话当前截图并保留已有消息上下文；该流程不运行自动意图分析。

普通截图的自动预测分支由用户在设置中管理。内置分支可以逐项关闭；用户可以新增指定截图类型和模型指令的自定义分支。没有启用的匹配分支时不自动请求模型，保留截图等待用户提问。

### 3.2 日程速记

例：截图文字“明天中午去望江楼吃饭”。

1. 点击“速记”后，AI 提取标题、日期、时间、地点与来源证据。
2. 展示可编辑草稿，明确区分截图原文、模型推断和用户设置的默认值。
3. “中午”可建议 12:00，但必须标记为建议；结束时间默认建议一小时后，同样标记。
4. 用户检查具体日期、时间、时区、地点和提醒设置后保存。
5. v0.1 显示“已保存到 Snipvia”；导出后显示“已导出，需在日历中完成导入”。

截图内如有消息日期，应优先作为“明天”的参照。无消息日期时，显示“按今天推算，请确认”，禁止把猜测伪装成截图中的确定信息。

### 3.3 无法直接生成日程

- “下周找时间聊聊”：缺少具体时间，进入待补充草稿，不创建确定事件。
- “老地方”：地点保留原文或待补充，不猜测地址。
- “周五前交方案”：识别为截止事项；v0.1 提供草稿，让用户明确选择截止提醒，不伪装成会议。
- “会议改到周三”：首版提示可能是改期，让用户手动处理原事件，不自动新增或覆盖。
- 多个事件：展示候选列表，每项单独确认；不静默批量写入。

## 5. 窗口与交互

- 常驻托盘/菜单栏，关闭业务窗口不等于退出；退出入口明确。
- 截图遮罩：十字光标、尺寸、拖动范围、Esc 提示。
- 对话浮窗：默认约 420×520 DIP，可调整大小；优先选区右侧，空间不足则左侧或下方，最终夹紧边界。移动截图时保留用户调整后的尺寸。
- 日程草稿：标题、具体日期、时间、时区、地点、提醒、来源图片、疑点提示、保存按钮。
- 主窗口：会话历史、日程列表、设置；不建设复杂月历拖拽编辑器。
- 连续触发快捷键不产生多个遮罩；对话回答期间截图，新建会话且响应按会话隔离。
- 关闭浮窗时停止当前网络生成，已保存内容仍在历史；取消截图不上传任何图像。

## 6. 时间、提醒和信任

- 时间显示采用当前用户时区；存储保留事件原时区，不因用户旅行而重解释事件。
- 日期确定但时间不明时允许用户选择全天；不得默认把所有不明时间设为 00:00。
- 结束时间必须晚于开始时间；提醒偏移不得为负；过去事件保存前明确提示。
- 夏令时不存在或重复的本地时间需要用户选择，不能静默偏移。
- 本地提醒依赖应用运行。退出、系统休眠、勿扰模式会影响通知；设置页和首次启用时说明。
- 唤醒或重启后检测过去 24 小时内漏发提醒，合并提示，不连发过期通知。
- 未接入外部日历时，不能承诺应用退出后仍准时通知。需要此能力的用户可导入外部日历。
- 只创建用户自己的日程；首版不邀请截图里的其他人、不发邮件。

## 7. 隐私与错误处理

- 只主动截图，不持续录屏或采集其他应用数据。进入框选时全屏帧仅暂存在内存，确认后只保留所选区域。
- 隐私说明必须明确：完成选区后自动理解可能把所选图片发往当前模型服务；框选中的全屏帧和取消的选区不会上传。
- API Key 明文不进入聊天记录、日志或 `settings.json`；按厂商使用 Electron `safeStorage` 加密，密文写入设置文件，macOS 以 `600` 权限和钥匙串保护，Windows 使用当前用户的 DPAPI。界面应说明 macOS 首次访问或应用身份变化可能触发钥匙串授权；本地数据库和图片不宣称默认加密。
- 支持关闭历史、删除会话及关联截图；已被日程引用的截图需告知保留原因，删除全部数据时一并清理。
- 网络失败保留输入和草稿；429/超时展示可重试操作；空回答、坏 JSON、无法识别都不能显示“成功”。
- 截图文字仅是待分析数据，不能授权软件执行命令或向他人发送信息。

## 8. 质量目标与验收

以下数字是待实测的目标，测试报告必须记录硬件、系统版本、显示器与网络条件。

| 维度 | 目标 |
| --- | --- |
| 本地唤起 | 已授权、预热后快捷键到可交互遮罩 p95 ≤ 500ms |
| 裁剪体验 | 松开鼠标到可交互浮窗 p95 ≤ 500ms，不含 AI |
| AI | 立即显示加载；首个输出目标 ≤ 5s，超过 10s 显示等待提示，可取消 |
| 稳定性 | 每个平台连续 100 次截取/取消/重试，无残留遮罩和崩溃 |
| 字段质量 | 冻结至少 100 条中英文标注样本，明确时间样本日期/时间字段准确率 ≥ 95% |
| 不确定信息 | 所有缺失日期或参照日的测试案例必须显式标记，不静默创建 |
| 本地提醒 | 系统唤醒且应用运行时，目标触发偏差 ≤ 30 秒 |
| 数据 | 重启后历史完整；重复点击不重复保存；删除后不可在应用中恢复 |

必测：Retina、Windows 100%/150%/200% 缩放、混合 DPI 副屏、负坐标屏幕、屏幕边缘、中文输入法、全屏应用、拒绝和撤销权限、断网、无图片能力模型、休眠唤醒、跨年“明天”、夏令时切换。

## 9. 待验证假设

用户是否愿意保持常驻、截图问答与速记哪个更高频、默认模型响应是否足够快、应用内日程是否能满足内测需求。若外部日历直写是目标用户的安装前提，应在对外发布前把 v0.2 日历接入提前，而不是将 ICS 导出包装成自动同步。
